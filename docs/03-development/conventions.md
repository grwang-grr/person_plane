# 设计和代码规范

## 通用约束

需求、建议和已实现功能要清晰区分。界面模块名称、导航层级和业务规则变更需先获得用户确认。保持文件职责单一，避免在页面组件中混合请求、复杂规则与存储操作。

## 前端

使用 TypeScript strict、明确的 Props 和可复用类型；组件 PascalCase、函数变量 camelCase。业务按 features 分目录，服务封装放 services。共享状态由 MobX 管理；路由负责当前项目、模块和历史记录。使用 workspace:\* 引用内部包，catalog: 引用外部依赖。格式化使用 oxfmt，静态检查使用 OxLint。

## 后端

使用类型标注、Pydantic 输入输出、SQLAlchemy 参数化查询和 Alembic 迁移。router、schema、service、repository 分工；跨对象约束不能只在前端检查。可预期错误返回明确状态码，日志不包含凭据和用户附件正文。Ruff 负责风格与导入检查。

## 测试与变更

功能测试覆盖实际行为、边界和失败场景。数据库测试和附件测试使用临时目录。锁文件随依赖变更提交。代码不得内置密钥、真实个人数据或自动加载演示业务数据。
