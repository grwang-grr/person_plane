# 2026-11-16 代码优化与验证

本轮沿用现有个人版结构和页面风格，重点处理日记、计划的数据一致性、查询效率与编辑体验。

## 接口与数据库

- 日记、计划、日历安排统一解析日期范围。无效日期、倒置区间返回 400，不再进入 ORM 查询后报错。
- 删除计划先校验范围。`this`、`future` 必须提供日期，未知范围返回 400，避免错误参数落到整条删除分支。
- 安排创建先验证 UUID、日期；不存在的计划返回 404。已删除计划的安排不再返回日历。
- 计划列表按日期范围预取有效安排，序列化复用预取结果与已加载的计划，不逐条回查数据库。
- 重复规则生成移至 `plane/utils/plan_recurrence.py`。单次删除保留为例外；修改标题、置顶和完成状态不重新生成安排。
- 重复间隔至少为 1，月日期为 1—31 或空。接口校验与数据库检查约束同时保证这些规则；周计划至少选择一个星期，重复计划需要开始日期。

SQLite 增量迁移为 `db.0005_plan_rule_constraints`，不改写基线迁移和用户正文。线上迁移前使用项目自带的 SQLite 一致性备份，备份同时包含数据库、附件与校验清单。

## 前端

- 日记编辑器按编辑会话初始化，后台重新获取列表不会覆盖本地草稿。
- 未保存状态覆盖关闭、切换日记、切换视图、路由离开及浏览器刷新；成功保存后解除提示。
- 保存中禁用表单，并通过 `inert` 临时阻止正文交互，保持富文本编辑器实例稳定。
- 统一解析服务层返回的 DRF 错误体和 Axios 错误。保存失败保留输入，展示实际字段错误。
- 复用新建、编辑计划的星期/月日期控件；编辑和新建保存期间阻止重复提交。
- 手机宽度下编辑器覆盖内容区域，避免固定 680px 编辑面板挤出屏幕。
- 加载占位内容保持服务端、浏览器首次渲染一致，避免主题初始化导致 hydration 失败。
- 修复文档实时配置为空和状态分组表单必填字段的类型错误。

## 验证命令

在 `upstream/plane/apps/api`：

```powershell
$env:DJANGO_SETTINGS_MODULE = 'plane.settings.personal'
.venv/Scripts/python.exe -m pytest -c pytest-personal.ini
.venv/Scripts/python.exe manage.py check
.venv/Scripts/python.exe manage.py makemigrations --check --dry-run
```

在 `upstream/plane`：

```powershell
pnpm --filter web check:types
pnpm turbo run build --filter=web
```

新增回归测试覆盖错误删除范围、非法规则、日期区间、安排改期与删除、查询次数和数据库约束。使用独立测试数据库验证页面；不使用真实业务数据作为测试样本。页面交互检查包含桌面和 390px 宽度。

前端类型检查与构建会同时使用 `.react-router/types`，必须顺序执行，避免生成文件被另一进程重建。个人版测试通过统一的 `personal_tests/conftest.py` 将附件、备份、数据锁等文件指向每项测试的临时目录，防止测试上传写入日常运行目录。

本机 Node 为 22.19.0，低于项目声明的 22.22.0；类型检查和构建可以通过，但会输出版本提示。没有调整项目要求或依赖锁文件。

## 发布与回退

构建后重启个人版服务，使 WhiteNoise 重新索引最新静态资源。只更新构建目录而不重启服务可能导致新资源地址返回 404。

只回退新增约束可执行 `manage.py migrate db 0004_diary_description_md`；回退应用代码时保持迁移版本匹配。完整数据恢复使用项目原有备份恢复流程，不直接覆盖运行中的 SQLite 文件。
