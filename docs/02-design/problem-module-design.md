# 问题模块设计草案

日期：2026-11-12。阶段：设计评审，未实现功能、接口或数据库迁移。

## 已确认的需求

- 新增全局“问题”入口，固定在侧栏底部，与“数据与备份”相邻，建议放在它的上方。
- 问题可以不关联任何对象，作为独立记录；也可以关联项目或具体任务。
- 选择任务后自动带出所属项目。
- 需要优先级等属性，直观表达问题的重要程度。
- 延续当前个人版的中文、免登录、Windows、本地 SQLite 和附件备份方式。

以下字段、状态及交互规则为本次设计建议，尚未作为最终业务规则确认。

## 定位与入口

问题台账记录已经发生、需要跟进解决的异常、缺陷或阻塞；任务记录计划执行的工作。问题独立建模，不将现有工作项直接改称问题。未来“风险”用于记录尚未发生的不确定事件，应另行设计。

全局入口展示全部问题；以后项目内的问题入口使用同一台账，预先筛选当前项目，不复制数据。任务详情可显示关联问题及未关闭数量。

建议路由为 /personal/problems/。沿用原版工作空间路由时，对应 /:workspaceSlug/problems/。避免与现有任务的 issues 路由混淆。

## 页面结构

### 列表

- 页头：“问题”、当前视图数量、右侧“新建问题”。
- 快捷视图：“未关闭”“重要”“已关闭”“全部”；默认“未关闭”。
- 工具栏：标题或编号搜索、项目筛选、更多筛选、显示设置。
- 默认列：编号与标题、关联对象、严重程度、优先级、状态、更新时间。
- 可选列：类型、标签、预计解决日期、关闭日期。
- 点击标题打开右侧详情；窄屏改为完整详情页，返回后保留筛选及滚动位置。
- 状态、优先级等同时显示文字和颜色，避免仅凭截图中的色点辨认。
- 每行更多菜单：编辑、复制链接、暂缓、关闭、重新打开、移至回收站；按当前状态显示可用操作。

“重要”视图建议包含优先级为紧急或高、或严重程度为致命或严重的未关闭问题；暂缓问题仍可在此出现，避免隐藏重要事项。

默认排序建议为优先级从高到低、严重程度从高到低、更新时间从新到旧。用户可切换排序；预计解决日期到期但未关闭的问题显示“已逾期”，不自动改变优先级或状态。

### 新建与编辑

建议采用宽表单：主要区域填写标题和问题说明，属性区域选择关联对象、分类、严重程度、优先级、日期和标签。必填项仅为标题；其他字段可使用默认值。

关联方式提供三个互斥选项：

| 方式 | 表单行为 | 保存结果 |
| --- | --- | --- |
| 独立问题 | 不要求项目或任务 | 两个关联字段均为空 |
| 关联项目 | 选择一个项目 | 保存项目，任务为空 |
| 关联任务 | 搜索项目内或跨项目任务，选项同时显示项目和任务编号 | 保存任务及它的所属项目 |

选择关联任务后，项目随任务同步；切换项目时如果已有不匹配的任务，先明确提示并清除任务关联，不能静默保留跨项目关系。清除任务后可保留当前项目，或选择“独立问题”一并清除。

底部按钮为“取消”“创建问题”；编辑时为“取消”“保存”。有未保存内容时离开需要提示。创建成功后可直接打开详情，不默认跳到任务。

### 详情

显示问题编号、标题、当前状态、关联项目和任务；主要内容包括问题说明、附件、处理记录、处理结果。右侧显示可编辑属性。

问题说明建议提示填写“现象、影响、复现步骤、期望结果”，同时允许自由记录，不将这些拆成多个必填字段。处理记录用于个人持续补充调查、尝试和结论，自动记录时间，不引入人员分配或审批。

## 字段建议

| 字段 | 规则或默认值 |
| --- | --- |
| 问题编号 | 系统生成，形如“问-000001”，个人工作空间内唯一、不可编辑、不重复利用 |
| 标题 | 必填，去除首尾空格，1 至 200 个字符 |
| 问题说明 | 可选，复用现有富文本和本地附件能力 |
| 关联项目、关联任务 | 可选；关联任务时项目必须与任务所属项目一致 |
| 类型 | 功能缺陷、数据异常、流程阻塞、体验改进、其他；默认“其他” |
| 严重程度 | 致命、严重、一般、轻微、待评估；默认“待评估” |
| 优先级 | 紧急、高、中、低；默认“中” |
| 状态 | 待处理、处理中、待验证、已关闭、暂缓；默认“待处理” |
| 标签 | 可选，可多选，问题模块使用自己的标签集合 |
| 预计解决日期 | 可选，仅日期；早于今天且未关闭时提示逾期 |
| 处理结果 | 平时可填写；关闭时建议必填，用于记录解决办法、无需处理或重复等结论 |
| 系统时间 | 创建时间、更新时间、关闭时间、删除时间，由系统维护 |

## 严重程度与优先级

严重程度回答“影响有多大”，优先级回答“先处理哪一个”。二者独立，不自动换算。优先级调整不修改严重程度，严重程度调整也不修改预计解决日期。

| 严重程度 | 判断参考 |
| --- | --- |
| 致命 | 核心功能无法使用、数据丢失或损坏，主要目标无法继续 |
| 严重 | 核心流程明显受影响，但存在临时解决办法 |
| 一般 | 局部功能异常，主要工作仍能继续 |
| 轻微 | 文案、样式或便利性问题，对结果影响较小 |
| 待评估 | 刚记录，尚未判断影响 |

| 优先级 | 处理顺序建议 |
| --- | --- |
| 紧急 | 优先立即处理，阻塞当前关键工作 |
| 高 | 尽快安排，优先于普通问题 |
| 中 | 按正常计划推进 |
| 低 | 可以延后，适合集中优化 |

例如：旧页面的严重缺陷可以具有高严重程度、低处理优先级；明天演示页面的一处轻微展示错误，可以具有轻微严重程度、高处理优先级。

## 状态与操作建议

主流程：待处理 → 处理中 → 待验证 → 已关闭。个人使用允许直接关闭，但建议要求填写处理结果；未填写时应停留在原状态。

- 未关闭问题可以暂缓；恢复暂缓后进入待处理。
- 已关闭问题可以重新打开，进入待处理并清除当前关闭时间，保留此前处理记录。
- 优先级、严重程度和标签不随状态自动变化。
- 记录状态变化、关联变化和处理结果变化的时间与前后值。
- 删除采用回收站，可恢复；第一阶段不提供永久清空。

## 关联对象的生命周期

- 项目或任务归档后，问题仍保留并可查看，关联处显示“已归档”；新建时默认不显示归档对象。
- 项目或任务软删除后，已有问题保留关联并显示“已删除”，不跟随级联删除；禁止新增到已删除对象。
- 如果未来提供永久删除关联对象，需要先明确解除关联或保留快照策略，不能在本模块中擅自实现级联删除。
- 任务移至其他项目后，问题的所属项目同步为任务的新项目，并记录关联变化。
- 一个问题第一阶段只关联一个项目和一个任务；跨项目影响可以在说明中记录，后续再设计多对象关联。

## 落地边界

在当前实际运行的 upstream/plane 中实现。建议使用 plane/personal 下独立的 Problem、ProblemEntry、ProblemLabel 及关联模型，任务外键复用原版 db.Issue，项目外键复用 db.Project；使用 UUID 主键，另设稳定的问题编号。

问题与风险尚未建表；本次设计不执行任何数据库修改。落地时通过 personal 应用的 Django migration 新建表，不覆盖 db 应用的 SQLite 基线迁移；先验证新旧数据备份。优先级和严重程度使用固定编码存储、中文文案显示，不翻译或修改既有任务的优先级编码。

现有完整 SQLite 备份将包含问题表；附件继续走本地文件目录和现有备份流程。问题说明、处理结果、附件均只在本机保存。

## 第一阶段建议验收范围

1. 左下角入口、问题列表、搜索筛选和排序。
2. 独立问题、项目问题、任务问题三种创建与编辑链路。
3. 问题详情、属性修改、处理记录、附件及关闭和重新打开。
4. 关联对象归档、删除和任务跨项目移动后的显示与约束。
5. 回收站恢复、完整备份包含问题与附件；所有界面使用中文。

暂不扩展为风险管理、工单审批或自动生成任务；如果后续需要“由问题创建处理任务”，应单独确认它与当前关联任务的关系。
